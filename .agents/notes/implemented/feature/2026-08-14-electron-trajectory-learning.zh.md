# Agent Note: Electron 轨迹证据学习模式

Status: implemented

[English](2026-08-14-electron-trajectory-learning.md) | 中文

## Problem

Trajectory 展示 Agent 运行的事件顺序和原始详情，但 System、Context、Request、Tool、Subtool 和 Compacted 等记录标签不能帮助非工程用户理解 agent loop 如何使用这些记录。学习视图必须解释可观察的 Agent 机制，同时不能虚构特定任务动机、把推理内容当作权威决策记录，也不能声称可以访问模型隐藏思考。

## Decision

Electron [Trajectory 呈现层](2026-08-14-electron-trajectory-localization.md)增加「逐步学习」开关。学习模式会为可选择的 Request 边界、时间线步骤和记录表条目显示悬停、聚焦与选中状态。点击或聚焦其中一项后，面板会针对该项更新三个明确字段：发生了什么、相关 Agent 知识，以及到原始 Trajectory 详情中的核对位置。

解释来自确定性目录，只使用已渲染记录的类型、序号、运行状态、错误状态、可见标签和工具名。界面提供相应信息时，面板会带入所选序号、状态、摘要和工具名，因此选择 `Tool：bash` 与选择一次模型 Request 会得到明显不同的讲解。目录讲解用户输入、模型可见上下文、系统提示词、模型请求、助手消息、顶层工具、嵌套 Subtool 和上下文压缩之间的关系，不读取或概述载荷内容。面板持续显示免责声明，说明它只使用可见事件和界面状态，既不展示也不猜测模型隐藏思考。

学习面板保留在 `apps/electron` 中，不修改上游 Trajectory 包或会话数据。原始 Trajectory 仍是证据来源；面板的每项解释都会指回用户可以检查的详情。

## Alternatives considered

**使用 LLM 生成每项解释。** 不采用，因为这会增加延迟、成本、不确定陈述，以及一次潜在敏感轨迹数据传输。稳定的记录分类体系已经足以支持所需的基础教学。

**把助手推理内容直接作为解释。** 不采用，因为已记录的推理内容是模型输出，不是运行时控制流的完整权威说明，并且隐藏思考不可用。提供方返回推理内容时，用户仍可在原始详情中查看。

**把教学目录加入上游 Trajectory 包。** 不采用，因为这是本地 Electron 学习需求，而且用户明确把改动限制在壳层。将目录保留在托管 Electron 覆盖层中，可以避免改变官方 Web 组合。

## Consequences

产品用户可以按照真实步骤逐项学习 Agent 核心机制，同时保留直接查看原始证据的路径。解释即时、无需密钥、可复现，并且不依赖所选 Trajectory 语言。

目录解释记录类别，不解释特定任务操作的唯一原因。上游新增记录类型仍会出现在原始 Trajectory 中，但在 Electron 目录完成分类前不会获得学习卡片。聚焦 DOM 测试覆盖选择、失败状态、语言隔离和隐藏思考免责声明；打包验证会对构建后的 renderer 重复这套交互。
